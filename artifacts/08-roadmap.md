# Roadmap

Phases are ordered by dependency, not by deadline. Finish a phase's exit
criteria before starting the next; if you must go out of order, say so in the PR.
Update the status boxes here as part of the work — a merged phase with stale
boxes is an incomplete phase.

## Phase 3 — Editor (done)

- [x] Node layer, wire layer, pin hit-testing, selection — [node-layer.tsx](../src/components/editor/node-layer.tsx) and [circuit-node.tsx](../src/components/editor/circuit-node.tsx) draw DOM nodes at world coordinates, [wire-layer.tsx](../src/components/editor/wire-layer.tsx) draws every wire in one SVG, and picking is arithmetic against the scene in [hit-test.ts](../src/state/hit-test.ts) rather than DOM hit-testing, so a target stays the same size in screen pixels at every zoom
- [x] Wiring gestures, rubber-band select, delete, duplicate, copy/paste — [use-editor-gestures.ts](../src/components/editor/use-editor-gestures.ts) and [use-editor-shortcuts.ts](../src/components/editor/use-editor-shortcuts.ts); the clipboard holds a document `Fragment`, not ids, so cut-then-paste works and a paste can cross documents
- [x] Wires bent by their waypoints — selecting a wire shows a handle on each bend, hovering one offers a new bend at the point under the cursor, and a drag inserts and places it as one undo step. Dropping a bend on its neighbour straightens the wire ([ADR 0007](decisions/0007-waypoint-handles.md))
- [x] Free-angle wires drawn click by click — a click on a pin arms a wire, clicks on empty canvas drop its bends, a click on a second pin lands it, all as one undo step. Segments run at any angle and corners are rounded at render time by `smoothPath` over the same polyline the hit-test uses ([ADR 0006](decisions/0006-free-angle-wires.md))
- [x] Palette + command menu, inspector driven by `paramsSchema` — [command-menu.tsx](../src/components/editor/command-menu.tsx) and [inspector.tsx](../src/components/editor/inspector.tsx), both generated from the registry and from each definition's `paramsSchema`, so neither names a node type. The inspector is a popover on the canvas, anchored to the selection's own world-space box, rather than a panel in the elements sidebar. It is split in two — the anchor box renders inside the canvas transform, the popover outside it — because a React portal bubbles events up the React tree, so a popup mounted under the canvas feeds every click in the form to the canvas pointer handlers
- [x] Palette batches with a ghost preview — a palette entry arms up to `MAX_PLACEMENT_COUNT` copies (click to add, right-click or `-` to remove), [ghost-layer.tsx](../src/components/editor/ghost-layer.tsx) draws them under the cursor at the snapped positions the click will use, and `placeNodes` drops the whole batch as one undo step. The layout is [`placementCenters`](../src/lib/circuit/geometry.ts), shared by the preview and the command so they cannot disagree
- [x] Toolbar: run controls, zoom, save/load, diagnostics panel — [run-controls.tsx](../src/components/editor/run-controls.tsx) and [diagnostics-panel.tsx](../src/components/editor/diagnostics-panel.tsx); zoom stays on the minimap where it already was
- [x] Per-project default zoom — [project-settings-panel.tsx](../src/components/editor/project-settings-panel.tsx), in the settings dialog opened from the canvas header menu ([settings-dialog.tsx](../src/components/editor/settings-dialog.tsx)), edits `defaultZoom` through a document command, so it is saved, exported and undoable; the canvas takes it as `defaultZoom`/`viewKey` and frames each circuit on open. Save format was **v2** at this point ([io.ts](../src/lib/circuit/io.ts)); branches later took it to v3
- [x] The minimap draws one footprint per connected group — [`sceneClusters`](../src/state/scene.ts) unions nodes joined by wires (a branch belongs to the wire it taps) and hands the canvas a box each, so two circuits far apart on one canvas read as two marks instead of one rectangle spanning the empty space between them. Derived from the scene, so it names no node type and nothing is stored; `contentBounds` on the canvas became `contentGroups`
- [x] The view a circuit is left at is remembered per project — pan and zoom are written to `logits:view:<id>` ([storage.ts](../src/state/storage.ts)) on the same debounce-and-flush shape as autosave ([use-view-persistence.ts](../src/components/editor/use-view-persistence.ts)), and the canvas takes the restored transform as `restoredView` alongside `viewKey`, so re-opening a circuit lands where it was left. Workspace state, not document state: it is per browser, never in the save format, and so needs no migration. "Reset view" is unchanged — it still goes to the origin at the project's `defaultZoom`. An example's view is not stored, for the same reason its edits are not ([ADR 0008](decisions/0008-examples-are-ephemeral.md))
- [x] The simulation store: [simulation.ts](../src/state/simulation.ts) owns an `Engine` and `Runner` per document and decides, per edit, between a rebuild and a live `setNodeParams` — which is what lets a switch be flipped mid-run without wiping the circuit's state
- **Exit:** a user builds a 4-bit adder from scratch with the mouse and sees it work. **Met** — place from the palette or `⌘K`, click pin to pin to wire, flip the switches, and the sums light the LEDs.

## Phase 4 — The rest of the nodes

- [x] Timing, sequential, combinational and memory blocks ([06-node-catalog.md](06-node-catalog.md)) — 45 definitions in the registry across nine categories. `seq.dff` and `seq.register` are one implementation with two pin sets, and so are `seq.jkff` and `seq.tff`; the reset/enable/clock frame every clocked node shares is [seq/shared.ts](../src/lib/nodes/seq/shared.ts). Two conventions about what an unwired pin means came out of writing them and are now [ADR 0009](decisions/0009-z-is-idle-on-a-control-pin.md)
- [x] Instruments: oscilloscope, 7-segment, hex display, bargraph — `emitSample` is now wired to a real ring buffer in [waveform.ts](../src/lib/sim/waveform.ts), which stores transitions only and is cleared by `reset()`. `scope.logic` has `delayNs: 0` so a sample lands at the transition, not a reaction time later, and its view subscribes with `useSimulationRevision` rather than snapshotting an array that could never compare equal
- [x] Entry and readout elements built on the same two files each — `comb.segdriver` decodes a value into segment lines for up to four `disp.sevenseg` displays at once, through the same `SEGMENT_PATTERNS` table the display's own BCD mode uses; `io.keypad` is a grid of momentary keys whose labels are its values, so a phone pad, a hex pad and a `RUN,STOP,STEP` pad are all the same element; `disp.matrix` is an n x n lamp panel wired a row at a time; and `io.kickstart` pulses once per reset, which is the power-on reset that gets a sequential circuit out of `X` before its first clock edge. `disp.segreadout` is that driver and its displays as one element — a value in, a number on the front, up to eight digits, with the decode shared through `readoutPatterns` rather than copied. Four new views ([keypad-view.tsx](../src/components/nodes/keypad-view.tsx), [matrix-view.tsx](../src/components/nodes/matrix-view.tsx), [segment-readout-view.tsx](../src/components/nodes/segment-readout-view.tsx), and the digit glyph both seven-segment views now share in [segment-digit.tsx](../src/components/nodes/segment-digit.tsx)) and three new icon names; nothing in the canvas, the engine, the palette or the inspector changed
- [x] `io.keyboard` — type into the circuit. Clicking the element captures the keyboard ([keyboard-view.tsx](../src/components/nodes/keyboard-view.tsx) stops every key before the editor's window listeners see it) until the configured exit chord (`Esc`, `Shift+Esc` or `Ctrl+]`), a click elsewhere, or window blur. Keys are logged into params with sequence numbers and drained into a FIFO by `evaluate`, so nothing coalesces away; ASCII, USB HID and PS/2 Set 2 encodings ([keyboard-codes.ts](../src/lib/nodes/io/keyboard-codes.ts)); handshake (`VLD`/`RD`) or strobe transfer; `OVF`, `CLR`, optional `BRK`. `NodeViewProps.setParams` gained a `coalesce` option so a typing session is one undo step
- [x] `io.drawpad` — a low-resolution pixel pad the user draws on, resolution and pixel size set in the inspector (up to 32 × 32). The picture is a `pixels` param, so it undoes and saves; it drives one bus per row (wires straight into `disp.matrix`) or an addressed `X`/`Y` read of `PX` and `ROW`. Pointer strokes are interpolated so a fast drag leaves no gaps and coalesce into one undo step, and there is a full keyboard path. Two files plus the view ([drawpad-view.tsx](../src/components/nodes/drawpad-view.tsx)) and one new icon name; nothing in the canvas, engine, palette or inspector changed
- [x] Buses: split/merge/tunnel — a tunnel has no `evaluate` at all. `buildNetlist` merges pins by name through the new `netAliases` hook on `NodeDefinition`, so two tunnels are genuinely one net and the netlist still knows no node types
- [x] Tunnel networks — the `group` hook: the name is a searchable network picker with an add row, joining adopts the network's width, a width edit applies to every tunnel on it, and selecting one highlights its peers
- [x] Subcircuits (user-defined chips) with port nodes and instancing. The **model** is `sub.port`, instances typed `sub.<key>`, definitions derived from the document by `subcircuitLookup`, and `flattenDocument` inlining them before the netlist is compiled ([ADR 0010](decisions/0010-subcircuits-are-derived-node-types.md)). The **authoring surface** is [subcircuit-commands.ts](../src/lib/circuit/subcircuit-commands.ts) — pure commands for making a chip out of a selection, renaming one, deleting one with its instances, and refusing a chip inside itself — plus an editor that treats editing a chip as a *path into the project* rather than a second editor ([ADR 0012](decisions/0012-editing-a-chip-is-a-path-into-the-project.md)): `editPath` in [document.ts](../src/state/document.ts) decides which document `getDocument()` returns, so every command, the scene, the netlist and the simulation work inside a chip unchanged, and history, autosave and the project id stay the root's. `createSubcircuit` groups the boundary **by net**, so two wires off one switch become one pin that fans out inside, and it keeps node and wire ids so a branch's anchor survives the move. On screen: `Ctrl+G` or **Make subcircuit** in the inspector, chips in the *Subcircuits* palette group with an ⋯ menu (edit / rename / delete), double-click or `Enter` on an instance to open it, a trail bar ([subcircuit-breadcrumb.tsx](../src/components/editor/subcircuit-breadcrumb.tsx)) to get back out, and chip commands in `Ctrl+K`. Flattening now also returns `pinAliases`, so an instance's pins show their values like any other node's, and `outerElementId` maps a diagnostic raised inside a chip onto the instance the canvas can actually mark
- **Exit:** every node in the catalog exists, each with a test. **Met**, the subcircuit editor included. Test harnesses for both kinds of node — a truth table and a real running circuit — are in [src/test/circuit.ts](../src/test/circuit.ts).

## Phase 5 — Polish

- [x] Per-element help in the palette — every entry has an info button opening [node-docs-dialog.tsx](../src/components/editor/node-docs-dialog.tsx). The prose is Markdown on the definition (`NodeDefinition.docs`), rendered by `react-markdown` through [ui/markdown.tsx](../src/components/ui/markdown.tsx); the pin and setting tables are *derived* from `pins()` and `paramsSchema` rather than restated, so they cannot drift. Adding a node still touches two files, and `registry.test.ts` fails a definition that ships without a page
- [x] Example circuits shipped with the app — ten documents in [`src/example/`](../src/example/), browsed in an examples dialog opened from the projects sidebar's ⋯ menu — a grid of cards with static thumbnails, each opening a running, operable but not editable `CircuitPreview` beside the grid, with **Import** to copy it into a new project ([examples-dialog.tsx](../src/components/projects/examples-dialog.tsx)). The largest, [calculator.json](../src/example/calculator.json), is a worked four-function calculator: one keypad, two four-digit operands, `+ − × ÷` on seven-segment readouts, with multiply and divide run as 14-clock shift-and-add / restoring-division loops. It is also the worked example of the annotations: every block sits in a titled `deco.group` tinted by role — blue for the clock, teal for the panels a user operates, green for the registers holding the numbers, purple for the key decode, amber for the decode glue, red for the arithmetic units, pink for the sequencer — laid out in six labelled columns that read left to right, each group followed by a `deco.text` note explaining how it works. It is the one example whose *behaviour* is tested, in [calculator.test.ts](../src/example/calculator.test.ts), by pressing keys and reading the registers the displays hang off. Every other example is annotated to the same pattern: one teal `deco.group` round the whole board carrying its name and one-line summary, tinted groups inside it for the stages — blue for what the user operates, green and amber for the logic, purple for outputs and waveforms — and `deco.text` panels headed **Try it** and then one heading per idea, placed down the right-hand side of a tall board or across the bottom of a wide one. The panels are several short notes rather than one long one because a blank line inside a note renders as nothing. They open *ephemeral*: fully editable and simulatable, but never written to storage, and "import" copies what is on screen into a new project ([ADR 0008](decisions/0008-examples-are-ephemeral.md)) The largest by part count, [snake.json](../src/example/snake.json), is a playable 16×16 Snake: an `io.keyboard` in HID strobe mode through a key-decoder ROM and a turn-filter ROM, a two-bit phase counter that splits every move into four clock edges (take the key and place food, read the tail, move the head, clear the tail), the body as a circular queue in `mem.ram` addressed by head and tail counters, a 16-register framebuffer where each row XORs itself with a one-hot mask steered by a single `comb.demux`, and an 8-bit XNOR LFSR for food. Its generator played it headless with a bot to a score of 12 before it shipped.
- [x] Pin names on the canvas — each pin labelled just inside the body on the edge it ended up on after rotation, on a chip in the node's own background so it stays readable over a view, drawn from `pins()` in [circuit-node.tsx](../src/components/editor/circuit-node.tsx) so no node type is named. Whether a node is labelled by default follows `NodeDefinition.kind` — `"basic"` (a gate, a switch: pins told apart by position) off, `"compound"` (a flip-flop, a mux: told apart only by name, and the default for a definition that says nothing) on — with a switch each in [editor-settings.ts](../src/state/editor-settings.ts). `registry.test.ts` fails a node that calls itself basic while putting two differently-named pins on one edge. Editor preferences, so neither is saved with a circuit. Where they are drawn is a second declaration, `NodeDefinition.pinLabels`: `"inline"` writes the name inside the body and reserves a gutter for it, `"floating"` — every `io.*` source and sink — hangs it outside and only while the node is hovered or selected, so a switch, an LED or a keypad never wears a label across the face that is the point of it — and answers to neither switch, since it carries no names until it is approached. Hover comes from the same scene hit-test as picking, since node bodies take no pointer events
- [x] A view per element, and a body that reads at every rotation — every definition names a `view`, and the ones with no symbol of their own name `"block"` ([block-view.tsx](../src/components/nodes/block-view.tsx)), so `grep 'view: "block"'` is the list still waiting for a real symbol. The block sets the element's name along whichever axis has the clear room, which is what stops a turned register reading `Regi ster`; `defineNode` widens or raises a footprint that cannot hold its name on one line at 8px, and the metrics behind both are shared in [label-metrics.ts](../src/lib/nodes/label-metrics.ts). Canvas names are the schematic ones — `NodeDefinition.shortTitle`: `MUX`, `DFF`, `REG` — while the palette, inspector and help keep the long `title`. `registry.test.ts` checks the one-line promise at all four rotations
- [x] Wire-to-wire connections drawn the natural way — a wire in progress lands on another wire the same way it lands on a pin: hovering one offers the tap as the hollow handle the bend gesture already uses, the wire in progress snaps its end to it, and the click joins them. `connectToWire` ([commands.ts](../src/lib/circuit/commands.ts)) makes the tap and the wire that reads it in one command, so it is one undo step, and stores the pair back to front — tap in `from`, the pin drawn from in `to`, bends reversed — because only `from` may be an anchor ([ADR 0011](decisions/0011-branches-are-wire-anchors.md)). `Alt` still drops a plain bend, which is how a wire crosses another without joining it
- [x] Pin direction by shape — an output (or `inout`) pin is drawn as a circle and an input as a rounded square in [circuit-node.tsx](../src/components/editor/circuit-node.tsx), so the two are told apart without relying on colour, which already carries the value
- [x] Performance monitor — a status line in the bottom-right corner (FPS, TPS, input latency, simulation speed) that the toolbar's activity button expands in place into a detailed view with 30 s sparklines and rendering / simulation / input / circuit figures. Sampled in its own rAF loop and published twice a second ([performance.ts](../src/state/performance.ts)), from totals the runner keeps (`Runner.stats`) and allocation-free windows in [rolling-window.ts](../src/lib/perf/rolling-window.ts). It is the instrument for the performance pass below, not that pass
- [x] Annotations: `deco.text` and `deco.group`, in a new *Annotations* palette category. Text is plain or basic Markdown (headings, emphasis, lists, quotes, code, links, tables; raw HTML skipped, images shown as alt text) rendered in `em` so it scales with its **Font size**, with ink and background tints so it doubles as a sticky note ([annotation-view.tsx](../src/components/nodes/annotation-view.tsx)). A group is a titled, tinted box with a subtitle and a filled / outlined / dashed style ([enclosure-view.tsx](../src/components/nodes/enclosure-view.tsx)). Neither has pins or an `evaluate`. Two new hooks carry everything the canvas does for them, so nothing in it names a type: **`resize`** — the params eight drag handles write, as one undo step through `resizeNode` / `setNodeFrame`, with the geometry in `resizeBox` ([geometry.ts](../src/lib/circuit/geometry.ts)) — and **`decoration`**, whose `enclosure` paints a group beneath the wires (`paintOrder` in [scene.ts](../src/state/scene.ts), rendered as a second `NodeLayer` pass), picks it only by header and edge, needs a band to surround it, and carries its contents on a drag (`withEnclosedNodes` in [hit-test.ts](../src/state/hit-test.ts)). The inspector gained a multiline `text` param and hides the label field for decorations. No save-format change: both are ordinary nodes
- [x] Notes are edited on the canvas. Double-clicking a `deco.text`, `Enter` on it, or **Edit text** in the inspector turns it into CodeMirror with draftly for the length of the session ([note-editor.tsx](../src/components/nodes/markdown/note-editor.tsx)), then back into static HTML. The preview is rendered through draftly once per distinct text and cached ([note-html.ts](../src/components/nodes/markdown/note-html.ts)), and sanitized against an allow-list with no images or raw HTML ([draftly.ts](../src/components/nodes/markdown/draftly.ts)). Only seven draftly plugins are used: paragraph, heading, inline, link, list, quote and rule, and the note's look is one draftly theme (`noteTheme`) that the editor mounts and `generateCSS` turns into the preview's stylesheet — generated and injected once — so a note looks the same while typed and at rest. The box grows taller with the text while it is edited, in the same undo step. A new `editInPlace` hook on the definition carries it, with a small store in [in-place-edit.ts](../src/state/in-place-edit.ts), so the canvas, the inspector and the shortcuts still name no type. No save-format change: the Markdown is still the `text` param
- [x] Project menus — every item in the canvas header menu works ([project-menu.tsx](../src/components/editor/project-menu.tsx)): New, Rename, Duplicate, Set view as origin, Import / Export, Settings → Preferences / Project settings, Keyboard shortcuts, Delete. The canvas only gives the menu a slot (`headerMenu`) and still knows nothing about projects. The delete confirmation was lifted out of the sidebar into [delete-project-dialog.tsx](../src/components/projects/delete-project-dialog.tsx), and it writes a pending autosave before deleting the open project, so letting go of the document cannot write it back. Sidebar rows open the same menu on right-click, with Duplicate and Export added. Import, from the toolbar, the header or the sidebar, now always creates a new project with a fresh id rather than loading the file over the open circuit under the file's own id. A `?` shortcut and [keyboard-shortcuts-dialog.tsx](../src/components/editor/keyboard-shortcuts-dialog.tsx) list the bindings; the list is hand-kept in step with 07-interaction-spec.md
- [x] Projects sidebar layout — the header is a **Logits** heading over the search field with a ⋯ menu beside it holding **New project** and **Import circuit file…**, with storage errors reported beneath them; the footer carries a "Star on GitHub" banner with an inline SVG illustration drawn in theme tokens ([github-star-banner.tsx](../src/components/projects/github-star-banner.tsx))
- [x] App-like selection and right-click — `body` is `select-none`; inputs, textareas, contenteditables (the CodeMirror note editor) and the node docs dialog opt back in ([globals.css](../src/app/globals.css)). [native-menu-guard.tsx](../src/components/native-menu-guard.tsx), mounted in the root layout, suppresses the browser's context menu outside editable fields without stopping propagation, so the canvas's wire branch, the palette's right-click and the project rows' menu still work
- [x] Read-only circuit preview — [circuit-preview.tsx](../src/components/preview/circuit-preview.tsx) runs, steps, resets and operates a circuit, pans and zooms it, and shows diagnostics and the performance monitor, all behind props, with no way to edit it. To make it possible: `simulation.ts` became a factory (`createSimulation`) provided through `SimulationContext`, with the editor on the default instance; the performance store is one per simulation; the simulation half of the toolbar was split into [simulation-controls.tsx](../src/components/editor/simulation-controls.tsx); `NodeLayer` takes its params writer as `onSetNodeParams`; and the canvas gained `showHeader`, `showSidebarToggle`, `defaultOffset`, `pannable`, `zoomable` and `dragToPan`. It fits the circuit on open with `fitViewport`. No save-format change
- [x] Embeddable preview route — `/preview#data=<link data>` ([app/preview/page.tsx](../src/app/preview/page.tsx)) renders one `CircuitPreview` full-frame for an `<iframe>` on another site, running on open. The document travels whole in the URL, deflated and base64url-encoded, through `encodeShareParam` / `decodeShareParam` in [io.ts](../src/lib/circuit/io.ts). It is in the fragment, decoded in the browser by [linked-preview.tsx](../src/components/preview/linked-preview.tsx), because the first `?data=` version failed with HTTP 431 on the calculator: its 126 KB link passed the server's ~16 KB request-line limit (it is 29 KB compressed). `?data=` links are still decoded on the server; a bad link shows the first load issue instead of a canvas. No save-format change
- [x] Shareable URL encoding — **Copy link** in the canvas header menu and in a sidebar project's menu, and a **Share** button in the canvas's top-right corner ([share-button.tsx](../src/components/editor/share-button.tsx)), all through `copyCircuitLink` in [project-actions.ts](../src/components/projects/project-actions.ts), put the circuit's `/preview` link on the clipboard
- [x] Agent skill for authoring circuits — [.claude/skills/logits-circuit/](../.claude/skills/logits-circuit/SKILL.md) teaches an agent to write `.logits.json` directly: node reference pages generated from the live registry by `gen-node-docs.sh` (so `docs`, pins and footprints are what `defineNode` actually produces), `pins.ts` for pin and stub coordinates, `check.ts` (load issues, netlist diagnostics, and a layout lint for diagonal wires, wires through bodies, look-alike junctions, clipped tunnel names, ungrouped or unlabelled parts, framing), `simulate.ts` for truth tables and stateful step files on the real engine, and a Playwright suite ([e2e/](../.claude/skills/logits-circuit/e2e/)) that opens the preview, fails on diagnostics, replays the same step file by clicking switches and screenshots every step. It prefers `/preview/example/<id>` and falls back to `/preview#data=` until that route exists. `@playwright/test` is a dev dependency, pinned to the Chromium build already cached
